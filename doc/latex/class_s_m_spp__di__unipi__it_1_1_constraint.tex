\subsection{Detailed Description}
base class of all possible type of constraints that a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_block}{Block}} can support 

The class \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_constraint}{Constraint}} is the base class of all the possible type of constraints that the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_block}{Block}} can support. This base class only supports a few fundamental facts\+:


\begin{DoxyItemize}
\item a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_constraint}{Constraint}} belong to one \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_block}{Block}};
\item a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_constraint}{Constraint}} is influenced by a set of \char`\"{}active\char`\"{} Variables, i.\+e., these which contribute to it being satisfied (or not)\+: hence, the class implements the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_thin_var_dep_interface}{Thin\+Var\+Dep\+Interface}} paradigm (i.\+e., derives from \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_thin_var_dep_interface}{Thin\+Var\+Dep\+Interface}}) that class makes no provisions about how this set is stored in order to leave more freedom to derived classes to implement it in specialized ways;
\item a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_constraint}{Constraint}} can be (temporarily?) relaxed, i.\+e., not really constraining the set of solutions of the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_block}{Block}};
\item a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_constraint}{Constraint}} can be either satisfied or not, depending on the values that its \char`\"{}active\char`\"{} Variables currently have;
\item a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_constraint}{Constraint}} has to be computed before it can be checked, and this can be costly (think multiple integrals for probability constraints or min-\/max functions requiring the solution of a hard optimization problem), which is why the class implements the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_thin_compute_interface}{Thin\+Compute\+Interface}} paradigm (i.\+e., derives from \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_thin_compute_interface}{Thin\+Compute\+Interface}}).
\end{DoxyItemize}

A fundamental design decision in S\+M\+S++ is that T\+HE \char`\"{}\+N\+A\+M\+E\char`\"{} OF A \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_constraint}{Constraint}} IS I\+TS M\+E\+M\+O\+RY A\+D\+D\+R\+E\+SS. This means that M\+O\+V\+I\+NG A \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_constraint}{Constraint}} IS N\+OT P\+O\+S\+S\+I\+B\+LE\+: copying a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_constraint}{Constraint}} to a different memory location makes a distinct \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_constraint}{Constraint}}.
