\subsection{Detailed Description}
class to describe modifications specific to a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_c05_function}{C05\+Function}} 

Derived class from \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_function_mod}{Function\+Mod}} to describe modifications to a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_c05_function}{C05\+Function}}. This class defines the following types of modifications\+:


\begin{DoxyItemize}
\item Alpha\+Changed
\end{DoxyItemize}

This type of modification states that the constant () of the linearizations has changed. Note, however, that this does {\itshape not} mean that $\ast$all the  have changed in the same way$\ast$; this happens if the whole function is shifted by a constant, which is what the original \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_function_mod}{Function\+Mod}} is intended to convey. Rather, the idea is that each individual  has changed in its own way, {\itshape but all the rest has remained unchanged} (unless other \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_modification}{Modification}} say otherwise). The idea is that it is possible to query the value of  for all the linearizations that were stored in the global pool \mbox{[}see get\+\_\+linearization\+\_\+constant()\mbox{]}, thereby re-\/using all the corresponding information to warm-\/start whatever algorithm one is using.

A case where this happens is the Lagrangian one, where each linearization is attached to one solution u\+\_\+i  U, and\+:


\begin{DoxyItemize}
\item either the objective function c of (P) changes;
\item or U itself changes to some U\textquotesingle{}  U.
\end{DoxyItemize}

In the first case, having stored u\+\_\+i in the global pool it is immediate to compute the new value of . In the second case, each u\+\_\+i is either feasuble (u\+\_\+i  U\textquotesingle{}) or not (u\+\_\+i  U\textquotesingle{}). In the first case  does not change, but in the second the original linearization (even the g part) can no longer be used, as it is no longer valid. This can be handled by having get\+\_\+linearization\+\_\+constant() returning Inf$<$\+Function\+Value$>$() for the corresponding .


\begin{DoxyItemize}
\item All\+Entries\+Changed
\end{DoxyItemize}

This type of modification states that all entries of previously computed linearizations (the g part) may have changed, {\itshape but all the rest has remained unchanged} (unless other \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_modification}{Modification}} say otherwise). It is then possible to query the new values of the linearizations that were stored in the global pool \mbox{[}see get\+\_\+linearization\+\_\+coefficients()\mbox{]}, thereby re-\/using all the corresponding information to warm-\/start whatever algorithm one is using.


\begin{DoxyItemize}
\item All\+Linearization\+Changed
\end{DoxyItemize}

This type of modification is the logical union of both previous types\+: for all of previously computed linearizations, both the g part and the  may have changed, {\itshape but all the rest has remained unchanged} (unless other \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_modification}{Modification}} say otherwise). It is then possible to query the new values of the linearizations that were stored in the global pool using the available methods as in the two previous cases.

A case where this happens is the Lagrangian one, where each linearization is attached to one solution u\+\_\+i  U, and the whole set of complicating constraints A u = b abruptly changes, whereas all the rest of (P) remains the same.
