\subsection{Detailed Description}
an observer that is interested in \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_modification}{Modification}} 

The \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_observer}{Observer}} class implements an observer as in the design pattern of the same name. This \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_observer}{Observer}} is only interested in \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_modification}{Modification}} and has the (pure virtual, which is why this is an abstract class) \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_observer_a4ac2234c8026ccbe13860a33fc4ef14e}{add\+\_\+\+Modification()}} method whereby the subjects can report the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_modification}{Modification}}.

In S\+M\+S++, \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_modification}{Modification}} has to reach the interested \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_solver}{Solver}}. This is usually done directly via the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_block}{Block}} (which is an \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_observer}{Observer}}), to which interested \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_solver}{Solver}} are attached (directly, or to any ancestor). However, the reason for a separate \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_observer}{Observer}} class is that \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_function}{Function}} objects can issue \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_modification}{Modification}}, but they may not be directly attached to a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_block}{Block}}; rather, they can, for instance, be inside a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_f_row_constraint}{F\+Row\+Constraint}} or a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_f_real_objective}{F\+Real\+Objective}} (which then themselves belong to a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_block}{Block}}), and with no direct knowledge of which of the two. Indeed, both \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_f_row_constraint}{F\+Row\+Constraint}} and \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_f_real_objective}{F\+Real\+Objective}} are \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_observer}{Observer}}.

Although this is not as yet implemented, this would also allows for having \char`\"{}\+Function of Function\char`\"{} objects (think Sum\+Fuction, Composite\+Function, ...) to be implemented, provided that \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_function}{Function}} itself is made an \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_observer}{Observer}}.

The \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_observer}{Observer}} class also supports the following notions\+:


\begin{DoxyItemize}
\item \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_modification}{Modification}} can be sent to \char`\"{}different channels\char`\"{}; besides the \char`\"{}default
  channel\char`\"{}, shipping them immediately to the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_solver}{Solver}}, new channels can be dynamically opened and closed that allow to bunch set of \char`\"{}logically
  related Modification\char`\"{} together in order to make it easier for the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_solver}{Solver}} to react to them.
\item The \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_observer}{Observer}} has a way for telling the observed object whether \char`\"{}nobody
  is listening\char`\"{}, and therefore there is no need to issue the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_modification}{Modification}} at all.
\item The \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_observer}{Observer}} provides a few convenience methods for formatting in an uniform way the parameter of calls to methods that produce \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_modification}{Modification}} which specifies if, how and where the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_modification}{Modification}} has to be issued. 
\end{DoxyItemize}
