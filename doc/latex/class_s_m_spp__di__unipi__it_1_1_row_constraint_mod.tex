\subsection{Detailed Description}
class to describe modifications specific to a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_row_constraint}{Row\+Constraint}} 

Derived class from \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_constraint_mod}{Constraint\+Mod}} to describe \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_modification}{Modification}} specific to a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_row_constraint}{Row\+Constraint}}, i.\+e., change its L\+HS / R\+HS.

Defining a class is a bit weird because the only thing the class does is to define am enum for the new value of the type of \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_modification}{Modification}} in the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_constraint_mod}{Constraint\+Mod}}. However, throwing a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_modification}{Modification}} of a different class (but derived from \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_constraint_mod}{Constraint\+Mod}}) may make it easier for the solver to handle it (at the very least, it directly knows it comes from a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_row_constraint}{Row\+Constraint}} without having to check it).
