\subsection{Detailed Description}
a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_constraint}{Constraint}} that is a \char`\"{}single row\char`\"{} 

The class \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_row_constraint}{Row\+Constraint}}, derived from \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_constraint}{Constraint}}, is intended as the base class for all the Constraints that are have a \char`\"{}row form\char`\"{}, that is,

L\+HS $<$= ( some function from \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_variable}{Variable}} to reals ) $<$= R\+HS

where L\+HS and R\+HS are two extended reals (hopefully at least one of which is finite and L\+HS $<$= R\+HS, but this is not enforced in the class). A type \char`\"{}\+R\+H\+S\+Value\char`\"{} is defined, which is bound by default to doubles, to hold the type of the L\+HS and R\+HS. Changing this type here is possible, but this changes it to the whole S\+M\+S++ hierarchy, so this does not look too reasonable; if one really needs a different return value than double she can rather re-\/define a similar class to this.

The above form encodes all possible kind of equality, inequality and ranged constraints. In this base class, {\itshape no assumption is done upon the form of the function}\+: typical examples are linear functions, quadratic functions etc., but this is dealt with in derived classes.

For many classes of problems this kind of \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_constraint}{Constraint}} naturally have a \char`\"{}dual\char`\"{} information attached \mbox{[}see \mbox{\hyperlink{_c_d_a_solver_8h}{C\+D\+A\+Solver.\+h}}\mbox{]}, which typically has the form of a {\itshape Lagrangian multiplier}\+: a single real value (in this case, again taken to be of type R\+H\+S\+Value). Support to this case is therefore offered by this class. This may be redundant in some cases, but if this really is a problem then a similar derived class from \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_constraint}{Constraint}} lacking the dual value can be easily defined.

On top of this the basic \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_constraint_mod}{Constraint\+Mod}}, other modifications are possible for this kind of \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_constraint}{Constraint}}, namely


\begin{DoxyItemize}
\item changing the L\+H\+S/\+R\+HS.
\end{DoxyItemize}

Yet, note that the base class does not explicitly store L\+HS and R\+HS values in order to allow more flexibility for derived classes to do that as they see better fit (for instance, not storing them at all if they are fixed). Thus, the methods for setting and changing these values (which are the ones to throw these \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_modification}{Modification}}) are pure virtual.

returns the absolute violation of the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_row_constraint}{Row\+Constraint}} 

The method computes and returns the absolute violation of the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_row_constraint}{Row\+Constraint}} corresponding to its current value \mbox{[}see \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_row_constraint_a42562ba0a608bdc52a80a2bb512d0603}{value()}}\mbox{]}. The value is positive if one of the two bounds is violated (of course not both can be) and it is the amount of violation; otherwise. An infinite bound (lhs == -\/ Inf$<$\+R\+H\+S\+Value$>$() or rhs == Inf$<$\+R\+H\+S\+Value$>$()) corresponds to a -\/ Inf$<$\+R\+H\+S\+Value$>$() violation whatever the value (even if it is the same infinity).

This method is provided because checking feasibility of a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_row_constraint}{Row\+Constraint}} should reasonably require numerical tolerances, which are not there in the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_constraint_a29e571bbd4e2f1046c56e39c06633c4c}{feasible()}} method (because in general constraints could be checked \char`\"{}exactly\char`\"{}, say if only integer arithmetic is involved).
