\subsection{Detailed Description}
base class for a Convex Duality Aware \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_solver}{Solver}} 

The {\itshape abstract} \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_c_d_a_solver}{C\+D\+A\+Solver}} class derives from \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_solver}{Solver}} \mbox{[}see \mbox{\hyperlink{_solver_8h}{Solver.\+h}}\mbox{]} and extends the interface of the base class to support the concept that it is Aware that (upper or lower, as appropriate) bounds on the optimal value of the problem are obtained by means of Convex Duality arguments. In other words, this is a Convex-\/\+Duality-\/\+Aware \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_solver}{Solver}}.

The main theoretical consequences of the fact that a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_solver}{Solver}} is based on the properties of convex sets/functions are\+:


\begin{DoxyItemize}
\item There typically is a {\itshape dual} problem, usually having {\itshape dual variables} associated to the constraints of the original (primal) problem, which can be used to obtain (upper or lower, as appropriate) bounds on the optimal value of the (primal) problem.
\item Since convex sets/functions \char`\"{}only go to infinity as (their recession)
  cones\char`\"{}; the fact that the objective function value of a model is unbounded below/above is basically equivalent to the fact that there exist an unbounded \mbox{[}a/de\mbox{]}scent direction, i.\+e., a direction along which one may go forever without leaving the feasible region and so that the objective function is \mbox{[}in/de\mbox{]}creasing indefinitely along it. This gives both a convenient {\itshape certificate of unboundedness} for unbounded models, and a convenient {\itshape certificate of infeasibility} for infeasible models via a convenient {\itshape certificate of unboundedness of their dual}.
\end{DoxyItemize}

Hence, this class does little more than extend the interface of \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_solver}{Solver}} to the concepts that\+:


\begin{DoxyItemize}
\item (multiple) dual solutions can be generated;
\item (upper or lower, as appropriate) bounds on the optimal value of the (primal) problem are associated to daid dual solutions, and therefore may change as different solutions are generated;
\item unbounded \mbox{[}a/de\mbox{]}scent directions can be produced for unbounded primal and dual problems, providing both convenient certificates of unboundedness and certificates of infeasibility;
\item the dual problem may be either an \char`\"{}exact\char`\"{} or an \char`\"{}inexact\char`\"{} one, i.\+e., strong duality holds, as opposed to only weak duality; in other words, being v(\+P) the optimal value of the primal (minimization) problem and v(\+D) the optimal value of the dual (maximization) problem, \begin{DoxyVerb}v(D) <= v(P)      (weak duality)
\end{DoxyVerb}


is always assumed to hold, but \begin{DoxyVerb}v(D) == v(P)      (strong duality)
\end{DoxyVerb}


may or may not hold, see \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_c_d_a_solver_a402db4cab5024abd480ae2186cf467cc}{is\+\_\+dual\+\_\+exact()}} (of course, the sign of the inequality is reversed if the primal is a maximization problem).
\end{DoxyItemize}

Regarding the second point, the interface of \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_c_d_a_solver}{C\+D\+A\+Solver}} does not really change that of \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_solver}{Solver}}, in that the methods \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_solver_a7304d819b2eeff3d4ba650055b24e3a5}{get\+\_\+ub()}} and \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_solver_a4a4dbe4c2416d531c4619ca94fc07d31}{get\+\_\+lb()}} remain the same. However, the following revision of the comments need to be taken into account\+:


\begin{DoxyItemize}
\item For get\+\_\+\mbox{[}lb/ub\mbox{]}() and a \mbox{[}min/max\mbox{]}imization problem, any returned finite \mbox{[}low/upp\mbox{]}er bound has to be considered as being attached to a feasible {\itshape dual} solution, in the sense of being its objective function value. If \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_c_d_a_solver_a347d37171494bf83416a48b279b94d5a}{get\+\_\+dual\+\_\+solution()}} has not been called yet after the last call to \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_solver_a504d4e3e174c7a518cc66156a8a45ce5}{compute()}}, then get\+\_\+\mbox{[}lb/ub\mbox{]}() should return the value of the best dual feasible solution ever found, the one which will be returned by the first call to \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_c_d_a_solver_a347d37171494bf83416a48b279b94d5a}{get\+\_\+dual\+\_\+solution()}} (if any). If \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_c_d_a_solver_a8c650415b6673c33692c363abdfdef00}{new\+\_\+dual\+\_\+solution()}} is called, it returns true, and get\+\_\+\mbox{[}lb/ub\mbox{]}() is called prior to the next call to \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_c_d_a_solver_a347d37171494bf83416a48b279b94d5a}{get\+\_\+dual\+\_\+solution()}} after that, then the value returned by get\+\_\+\mbox{[}lb/ub\mbox{]}() will be the value of the {\itshape new} dual solution, the one that has {\itshape not} been written into the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_block}{Block}} (in the specific way of the current model, e.\+g., in terms of dual variables attached to the Constraints) yet, and that will be written when \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_c_d_a_solver_a347d37171494bf83416a48b279b94d5a}{get\+\_\+dual\+\_\+solution()}} is called (if ever). Hence, the value returned by get\+\_\+\mbox{[}lb/ub\mbox{]}() may change immediately after a call to \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_c_d_a_solver_a8c650415b6673c33692c363abdfdef00}{new\+\_\+dual\+\_\+solution()}}. This is so that the caller may know beforehand the value of the dual solution that is returned before it is even written to the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_block}{Block}} (it is assumed that this is know basically for free by the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_solver}{Solver}}), which can help her to decide whether or not the cost of writing (and then reading) is worth. The sequence of values of solutions returned by successive calls to get\+\_\+\mbox{[}lb/ub\mbox{]}() (after calls to \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_solver_af109b504a566c90a4ea45c1574c128fe}{new\+\_\+var\+\_\+solution()}} that return true) is expected to be generically \char`\"{}improving\char`\"{}, i.\+e., solutions with \mbox{[}smaller/larger\mbox{]} values are reported first; however, this does not need to be strictly enforced by the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_solver}{Solver}}, except that the first value ever reported should always be the best \mbox{[}low/upp\mbox{]}er bound available. Note, however, that the link between \mbox{[}lo/upp\mbox{]}wer bounds and solutions only holds if the solution itself is dual feasible \mbox{[}see \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_c_d_a_solver_a974e986ce1a04d44660bb5c573e8315d}{is\+\_\+dual\+\_\+feasible()}}\mbox{]}; if dual unfeasible solutions are generated, the value returned by get\+\_\+\mbox{[}lb/ub\mbox{]}() may (necessarily have to) be different from their objective function value.
\end{DoxyItemize}

Similarly, the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_c_d_a_solver}{C\+D\+A\+Solver}} class re-\/uses and extends the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_solver_ae1717d1363782e086aa797e7437c0352}{set\+\_\+unbounded\+\_\+threshold()}} method to produce \char`\"{}arbitrarily good\char`\"{} dual solutions when the dual problem is unbounded, which implies that the primal one is infeasible. That is, when \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_solver_a504d4e3e174c7a518cc66156a8a45ce5}{compute()}} returns k\+Infeasible, the method can be used to set a threshold thr such that each subsequent call to \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_c_d_a_solver_a8c650415b6673c33692c363abdfdef00}{new\+\_\+dual\+\_\+solution()}} / \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_c_d_a_solver_a347d37171494bf83416a48b279b94d5a}{get\+\_\+dual\+\_\+solution()}} only produces (new) dual solutions that\+:


\begin{DoxyItemize}
\item for a primal minimization problem, which means that the dual is a maximization one, have objective function value $>$= thr;
\item for a primal maximization problem, which means that the dual is a minimization one, have objective function value $<$= thr.
\end{DoxyItemize}

There is no need for a separate \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_solver_ae1717d1363782e086aa797e7437c0352}{set\+\_\+unbounded\+\_\+threshold()}} method for the dual problem because there is no risk that both problems are simultaneously unbounded\+: to which of the two the threshold necessarily refers is immediately obvious from the return code of \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_solver_a504d4e3e174c7a518cc66156a8a45ce5}{compute()}}.

It should also be noted that, since the dual of a minimization model is a maximization one and vice-\/versa, the interpretation of upper cutoffs and lower cutoffs \mbox{[}see dbl\+Up\+Cut\+Off and dbl\+Lw\+Cut\+Off in \mbox{\hyperlink{_solver_8h}{Solver.\+h}}\mbox{]} can be done both in terms of the primal and of the dual problem. For instance, assue an upper cutoff  is set for a minimization problem\+: the condition

lb $>$= 

means {\itshape both}\+:


\begin{DoxyItemize}
\item for the primal problem, that is a minimization one, the condition says that a solution with objective function value at least as good as (i.\+e., smaller than)  was needed, but it is now clear that this is never going to happen, so the problem is treated as being as being detected to be unfeasible and the algorithm can stop already;
\item for the dual problem, that is a maximization one, the condition says that a solution with objective function value at least as good as (i.\+e., greater than)  was needed; this has already been found, so the problem is treated as being solved already and the algorithm can stop.
\end{DoxyItemize}

Of course, this is symmetric if the primal is a maximization problem.

A call to \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_solver_a504d4e3e174c7a518cc66156a8a45ce5}{compute()}} that returned k\+Infeasible supposedly mean that the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_c_d_a_solver}{C\+D\+A\+Solver}} can guarante that it is impossible to find any feasible solution to the primal problem. This typically (but not always, see k\+Both\+Infeasible) means that it is possible to find feasible {\itshape dual} solutions whose value is \char`\"{}better\char`\"{} than any given threshold. For models with underlying convex structure, this typically means that there exist an unbounded \mbox{[}a/de\mbox{]}scent direction in the dual space, i.\+e., a direction along which one may go forever without leaving the feasible region of the dual and so that the dual objective function is \mbox{[}in/de\mbox{]}creasing indefinitely along it. This gives both a convenient {\itshape certificate of unboundedness} of the dual, and a convenient {\itshape certificate of infeasibility} for the primal. Hence, the user may be interested in accessing one (or more) of these directions. This can be done implicitly and indirectly via \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_solver_ae1717d1363782e086aa797e7437c0352}{set\+\_\+unbounded\+\_\+threshold()}} \mbox{[}see the general comments\mbox{]}, but a more direct representation may be useful.

Called after \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_solver_a504d4e3e174c7a518cc66156a8a45ce5}{compute()}} that returned k\+Infeasible, this method has to return true if an unbounded dual \mbox{[}a/de\mbox{]}scent direction is available to be read with \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_solver_a4bc119810c0c2ee3ba0c48183f50aaf4}{get\+\_\+var\+\_\+direction()}}. It is often the case that such a direction is \char`\"{}automatically\char`\"{} available as a by-\/product of \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_solver_a504d4e3e174c7a518cc66156a8a45ce5}{compute()}} whenever the latter returns k\+Infeasible; hence, this method is typically (but not necessarily) true after the end of \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_solver_a504d4e3e174c7a518cc66156a8a45ce5}{compute()}} whenever k\+Infeasible is returned.

Once \char`\"{}the first\char`\"{} direction (if ever) has been read, new ones may be produced, if the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_solver}{Solver}} allows it, by means of \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_c_d_a_solver_ad83925e362d49bbe570a881791e45ea0}{new\+\_\+dual\+\_\+direction()}}.

This method returns true if the dual problem is an \char`\"{}exact\char`\"{} one. That is, being v(\+P) the optimal value of the primal (minimization) problem and v(\+D) the optimal value of the dual (maximization) problem, this method returns true only if it is theoretically guaranteed (which, usually, means that it is also practically true) that \begin{DoxyVerb}  v(D ) == v(P)      (strong duality)

\end{DoxyVerb}


is always assumed to hold, regardless to the return value of this method. Of course, the sign of the inequality is reversed if the primal is a maximization problem.

Most often, the return value of this method will be constant for a whole class of problems, i.\+e., for a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_c_d_a_solver}{C\+D\+A\+Solver}} irrespectively of the data of the actual problem to be solved\+: a class of problems either has a strong dual, or it has not. However, in some cases strong duality may depend on the instance of the model (e.\+g., if some appropriate constraint qualification holds).

The method is given a default implementation in the base \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_c_d_a_solver}{C\+D\+A\+Solver}} class catering the very lucky case in which the dual is exact. \mbox{\Hypertarget{class_s_m_spp__di__unipi__it_1_1_c_d_a_solver_a974e986ce1a04d44660bb5c573e8315d}\label{class_s_m_spp__di__unipi__it_1_1_c_d_a_solver_a974e986ce1a04d44660bb5c573e8315d}}

The method has to return true if a dual solution that is {\itshape different} from the previously available one is available. This method returning false means that the C\+D\+Solver has no means of producing any other dual solution for good, so it does not make sense to call it again unless something has changed in the problem encoded in the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_block}{Block}} \mbox{[}see the discussion in \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_solver_a504d4e3e174c7a518cc66156a8a45ce5}{compute()}}\mbox{]} or, in case the last call to \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_solver_a504d4e3e174c7a518cc66156a8a45ce5}{compute()}} has returned k\+Stop\+Time or k\+Stop\+Iter, \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_solver_a504d4e3e174c7a518cc66156a8a45ce5}{compute()}} is called again. For a typical algorithm that only produces one dual solution, this method should always return false; indeed, this is what the default implementation of the method does.

The user can restrict the set of generated dual solutions, both in number (see int\+Max\+D\+Sol) and in terms of their quality (see dbl\+R\+Acc\+D\+Sol and dbl\+A\+Acc\+D\+Sol) or feasibility (see dbl\+F\+Acc\+D\+Sol). In particular, note that the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_c_d_a_solver}{C\+D\+A\+Solver}} may be instructed (via dbl\+F\+Acc\+Sol) to also return {\itshape unfeasible} dual solutions if it has produced any (which may be the case if, for instance, the models is dual infeasible, and therefore no feasible dual solution can ever be found). This means in particular that it is in principle sensible to call this method even if \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_solver_a504d4e3e174c7a518cc66156a8a45ce5}{compute()}} has returned a value not necessarily implying that a dual solution has been found (like k\+Low\+Precision or k\+Error), and even if it is guaranteed that no dual solution exists, i.\+e., either k\+Unbounded or k\+Both\+Infeasible.

While producing its dual solutions, it is expected that a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_c_d_a_solver}{C\+D\+A\+Solver}} should\+:


\begin{DoxyItemize}
\item return first feasible dual solutions, if any, and only after having exhausted them start returning infeasible ones;
\item return feasible dual solutions, at least roughly, in order of their objective function values, i.\+e., the better ones first (and in particular, the absolute best solution ever found as absolute first);
