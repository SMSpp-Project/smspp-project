\subsection{Detailed Description}
class to describe modifications specific to a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_f_real_objective}{F\+Real\+Objective}} 

Derived class from \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_objective_mod}{Objective\+Mod}} to describe \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_modification}{Modification}} specific to a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_f_real_objective}{F\+Real\+Objective}}, i.\+e., changing the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_function}{Function}}.

Defining a class is a bit weird because the only thing the class does is to define am enum for the new value of the type of \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_modification}{Modification}} in the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_objective_mod}{Objective\+Mod}}. However, throwing a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_modification}{Modification}} of a different class (but derived from \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_objective_mod}{Objective\+Mod}}) may make it easier for the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_solver}{Solver}} to handle it (at the very least, it directly knows it comes from a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_f_real_objective}{F\+Real\+Objective}} without having to check it).
