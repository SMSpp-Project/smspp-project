This project covers two conceptually different things (which may one day be splitted to two different projects)\+:


\begin{DoxyItemize}
\item M\+C\+F\+Block, a S\+M\+S++ \+:Block for Linear Min-\/\+Cost Flow Problems
\item M\+C\+F\+Solver, a S\+M\+S++ \+:Solver for M\+C\+F\+Block based on forwarding the interface of (objects derived from the general abstract) \href{http://www.di.unipi.it/optimize/Software/MCF.html}{\tt M\+C\+F\+Class of the M\+C\+F\+Class project}
\end{DoxyItemize}

The project obviously requires the \href{https://gitlab.com/frangio68/sms_plus_plus}{\tt \char`\"{}core\char`\"{} S\+M\+S++}; however, it also requires (for the M\+C\+F\+Solver component) the \href{https://github.com/frangio68/Min-Cost-Flow-Class}{\tt M\+C\+F\+Class project}.

The arrangement of folders is assumed to be \begin{DoxyVerb}some root folder
 |
 +- SMS++ (the "core" SMS++)
 |
 +- MCFBlock (this project)
 |
 +- MCFClass (the MCFClass project)
\end{DoxyVerb}


M\+C\+F\+Block/test contains a reasonably sophisticated test that takes some existing M\+CF instance in the D\+I\+M\+A\+CS standard format, reads it into a M\+C\+F\+Block and an \+:\mbox{\hyperlink{class_m_c_f_class}{M\+C\+F\+Class}} object, create a M\+C\+F\+Solver using the very same \+:\mbox{\hyperlink{class_m_c_f_class}{M\+C\+F\+Class}} solver, and then repeatedly modifies both instances in the same way (possibly passing to a \char`\"{}copy\char`\"{} R3\+Block of the initial M\+C\+F\+Block) in order to verify that the different Modification involved correctly do their work.
