This is a very small project aimed at providing a very simple example of a S\+M\+S++ \+:Block that only has the \char`\"{}abstract implementation\char`\"{} in terms of F\+Row\+Constraint and F\+Real\+Objective whose underlying Function is Linear; basically, a (MI)LP. Besides these, One\+Var\+Constraint(s) are also allowed to more efficiently handle bound (sign) constraints.

However, in order to cater for the inherent composability of Block, two different classes are implemented\+:


\begin{DoxyItemize}
\item Simple\+M\+I\+L\+P\+Block is a \char`\"{}leaf\char`\"{} M\+I\+LP block, i.\+e., it has a single set of Col\+Variable x, a single linear objective function in these, a single set of linear constraints in these, and no \char`\"{}inner\char`\"{} Block.
\item Structured\+M\+I\+L\+P\+Block derives from Simple\+M\+I\+L\+P\+Block and therefore shares all its features; however, it may have any number of \char`\"{}inner\char`\"{} Block, which may be either Simple\+M\+I\+L\+P\+Block or Structured\+M\+I\+L\+P\+Block (so that a tree-\/shaped M\+I\+LP with any degree of nesting can be represented). Hence, a Structured\+M\+I\+L\+P\+Block also has a set of \char`\"{}linking\char`\"{} constraints in its x variables and in the x variables of its inner S\mbox{[}imple/tructured\mbox{]}M\+I\+L\+P\+Block.
\end{DoxyItemize}

The project obviously requires the \char`\"{}core\char`\"{} S\+M\+S++, avalable at \begin{DoxyVerb}https://gitlab.com/frangio68/sms_plus_plus
\end{DoxyVerb}


The arrangement of folders is assumed to be \begin{DoxyVerb}some root folder
 |
 +- SMS++ (the "core" SMS++)
 |
 +- SMILPBlock (this project)
\end{DoxyVerb}


S\+M\+I\+L\+P\+Block/test contains a simple test main that reads M\+I\+LP problems from files in a custom test-\/based format and serialize/deserialize them in/from Net\+C\+DF files.
