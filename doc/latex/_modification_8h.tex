\subsection{Detailed Description}
Header file for the {\itshape abstract} class Modification, basically only the top of the hierarchy of (small) objects describing the differenc changes that can occur to the various pieces of a S\+M\+S++ model, in the classes \mbox{[}derived from\mbox{]} Block, Variable, Constraint, Objective. Modification primarily serve to ensure any \char`\"{}interested\char`\"{} Solver is made aware of the changes and can efficiently react to them.

However, Modification also have another crucial role\+: those that are issued when the \char`\"{}abstract representation\char`\"{} of a \+:Block is modified are used by the \+:Block to ensure that the \char`\"{}physical representation\char`\"{} of the \+:Block (if any) is kept in synch with the abstract one. This is why the derived class A\+Moodification is also defined, which has ways to \char`\"{}tell\char`\"{} a \+:Block whether the changes have still to be applied to its \char`\"{}physical
representation\char`\"{}, or this has already be done.

Some changes in a Block may trigger more than one Modification. For instance, when a (dynamic) Variable is removed from a Block \mbox{[}see Block\+::remove\+\_\+dynamic\+\_\+variables()\mbox{]}, it is (unless otherwise stated) also removed from every \char`\"{}stuff\char`\"{} (Constraint, Objective, Function, ...) it is active in. It may be helpful for a Solver (or a Block, if this is an \char`\"{}abstract Modification\char`\"{} that still has to be used to ensure that its \char`\"{}physical representation\char`\"{} of the is kept in synch with the abstract one) to know beforehand that some Modification are \char`\"{}logically related\char`\"{}. This is why the Group\+Modification class is also defined, which is simply a container that holds a list of std\+::shared\+\_\+ptr$<$\+Modification$>$. This cannot complicate (too much) the handling of Modification by a Solver (or Block), because if the Solver (Block) is not \char`\"{}interested\char`\"{} in the \char`\"{}logical relation\char`\"{} between the individual Modification in the Group\+Modification it can simply process them sequentially as if they were individual ones. Conversely, having a Group\+Modification may in principle considerably simplify the handling.
