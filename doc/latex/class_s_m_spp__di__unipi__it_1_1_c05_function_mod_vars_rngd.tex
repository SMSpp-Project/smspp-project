\subsection{Detailed Description}
class to describe changes to a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_c05_function}{C05\+Function}} involving a range of \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_variable}{Variable}} 

Derived class from \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_function_mod_vars_rngd}{Function\+Mod\+Vars\+Rngd}} to describe changes specific to a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_c05_function}{C05\+Function}}. This class defines the following type of modification\+:


\begin{DoxyItemize}
\item Some\+Entries\+Change
\end{DoxyItemize}

\char`\"{}extending\char`\"{} function\+\_\+mod\+\_\+variables\+\_\+type, and, basically, does nothing else.

It is, however, important to extensively comment how the information in this \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_modification}{Modification}} relates to changes in the {\itshape linearization}, that are specific to \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_c05_function}{C05\+Function}}. The point is simply that each entry of any linearization vector is uniquely associated to a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_variable}{Variable}}, and therefore the \char`\"{}name = pointer\char`\"{} of the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_variable}{Variable}} can be used as an \char`\"{}index\char`\"{} in the linearization vector. Therefore, the the f\+\_\+strt and f\+\_\+stop fields of the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_function_mod_vars_rngd}{Function\+Mod\+Vars\+Rngd}} can be transformed into indices in the linearization vector by means of \mbox{\hyperlink{group___thin_var_dep_interface___c_l_a_s_s_e_s_ga05297a4e506f89ec692a01aca971ce2d}{Thin\+Var\+Dep\+Interface\+::is\+\_\+active()}}.

In particular, Some\+Entries\+Change indicates that some entries of {\itshape all} previously computed linearizations may have changed and must be updated in order for them to reflect linearizations of the current function. The (\mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_variable}{Variable}} names corresponding to the) indices of the components of the linearization vector that must be recomputed are all those in the range specified by the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_function_mod_vars_rngd}{Function\+Mod\+Vars\+Rngd}}. It is then possible to query the new values of the corresponding entries of the linearizations that were stored in the global pool \mbox{[}see get\+\_\+linearization\+\_\+coefficients()\mbox{]}, thereby re-\/using all the corresponding information to warm-\/start whatever algorithm one is using.

A case where this happens is the Lagrangian one, where each linearization is attached to one solution u\+\_\+i  U, and {\itshape some} of the complicating constraints A u = b abruptly changes, whereas all the rest of (P) remains the same. Having stored the u\+\_\+i in the global pool it is immediate to compute the new values of g for the appropriate entries.

Note that if all the entries change, this can be somehow more clearly and succinctly signaled by issuing a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_c05_function_mod}{C05\+Function\+Mod}} with type All\+Entries\+Changed (or All\+Linearization\+Changed); however, this is the same as a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_function_mod_vars_rngd}{Function\+Mod\+Vars\+Rngd}} with strt == stop == nullptr.

Since this \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_modification}{Modification}} derives from \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_function_mod_vars}{Function\+Mod\+Vars}}, it also in principle supports the


\begin{DoxyItemize}
\item Add\+Var
\item Remove\+Var

types. Indeed, this makes full sense for the removal\+: the provided range uniquely identifies the N \char`\"{}active\char`\"{} \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_variable}{Variable}} that need be removed, which obviously correspond to a contiguous range of N entries in the linearization vectors, and removing these \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_variable}{Variable}} \char`\"{}simply\char`\"{} correspond to cutting away that range from all previous linearization vectors; this can be done without any further input from the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_c05_function}{C05\+Function}}. Note that, of course,

T\+H\+IS O\+N\+LY H\+O\+L\+DS IF T\+HE \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_c05_function}{C05\+Function}} IS Q\+U\+A\+S\+I-\/\+A\+D\+D\+I\+T\+I\+VE

(see comments to \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_function_mod_vars}{Function\+Mod\+Vars}}), which is signalled by the value of shift. If shift == Inf$<$\+Function\+Value$>$(), one has to assume that all the entries of the previous linearizations have changed.

A case where this happens is the Lagrangian one, where each linearization is attached to one solution u\+\_\+i  U, in the sense that the vector is g\+\_\+i = b -\/ A u\+\_\+i. Removing one complicating constraints A\+\_\+h u = b\+\_\+h simply corresponds to removing the h-\/th row of g\+\_\+i.

However, this form of \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_modification}{Modification}} does not lend itself well to handling the {\itshape addition} of N \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_variable}{Variable}}. For this to be done, the pointers to all new \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_variable}{Variable}} need be retrieved\+: the only way to do this with range information is to assume that both strt and stop belong to an array of \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_variable}{Variable}}, so that all the ones \char`\"{}between\char`\"{} are added. However, this would require knowing {\itshape exactly which type of \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_variable}{Variable}}} these are. Although the possibility is left open for some specific \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_function}{Function}} to use, it is not possible to use \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_c05_function_mod_vars_rngd}{C05\+Function\+Mod\+Vars\+Rngd}} in full generality to handle addition of \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_variable}{Variable}}, even if the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_function}{Function}} is quasi-\/additive. 
\end{DoxyItemize}
