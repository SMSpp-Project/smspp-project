\subsection{Detailed Description}
derived class from \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_configuration}{Configuration}} for the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_thin_compute_interface}{Thin\+Compute\+Interface}} parameters 

Derived class from \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_configuration}{Configuration}} to describe all the parameters that a \+:\mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_thin_compute_interface}{Thin\+Compute\+Interface}} may have (derived classes only, of course, the base class is thin and does not have any).

The class holds three lists\+:


\begin{DoxyItemize}
\item a list of pairs $<$ string , int $>$
\item a list of pairs $<$ string , double $>$
\item a list of pairs $<$ string , string $>$
\end{DoxyItemize}

The idea is that each list contains the pairs $<$ parameter name , value $>$ to be changed/set. The lists need {\itshape not} contain all the parameters (of the given type), all those not directly specified are treated as speficied in the bool field f\+\_\+diff. If f\+\_\+diff == true, then the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_compute_config}{Compute\+Config}} has to be \char`\"{}interpreted in a differential sense\char`\"{}\+: all parameters not specified must not be changed from their current value. If f\+\_\+diff == false instead, then all the parameters that are {\itshape not} specified in the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_compute_config}{Compute\+Config}} are rather reset to their default value. Note that the same holds for the provided field f\+\_\+extra\+\_\+\+Configuration, which allows to specify an arbitrary extra \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_configuration}{Configuration}} object\+: if f\+\_\+diff == true and f\+\_\+extra\+\_\+\+Configuration == nullptr this has to be interpreted as \char`\"{}leave the previous extra
\+Configuration as it is\char`\"{}, whereas if f\+\_\+diff == false then the current extra \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_configuration}{Configuration}} is replaced by that in the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_compute_config}{Compute\+Config}} (which may be nullptr; depending on the \+:\mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_thin_compute_interface}{Thin\+Compute\+Interface}} this may be implemented by just storing the nullptr, or by resetting that part of the configuration to its default value as the rest). Note, however, that for a \char`\"{}fresh\char`\"{} (just constructed) solver, the two values of f\+\_\+diff are equivalent.

It is always possible to define a specific \+:\mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_compute_config}{Compute\+Config}} corresponding to a specific \+:\mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_thin_compute_interface}{Thin\+Compute\+Interface}}, but the fact that the set of parameters is freely extendable together with the flexibility provided by the extra \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_configuration}{Configuration}} field may be enough to cover many use cases without a specific \+:\mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_compute_config}{Compute\+Config}} class definition.
