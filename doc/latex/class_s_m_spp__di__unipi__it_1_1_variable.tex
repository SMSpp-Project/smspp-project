\subsection{Detailed Description}
base class of all possible type of variables that a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_block}{Block}} can support 

The class \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_variable}{Variable}} is the base class of all the possible type of variables that the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_block}{Block}} can support. This base class only supports a few fundamental facts\+:


\begin{DoxyItemize}
\item a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_variable}{Variable}} belongs to one \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_block}{Block}};
\item a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_variable}{Variable}} influences a set of different objects, gathered below the abstract class \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_thin_var_dep_interface}{Thin\+Var\+Dep\+Interface}} (\mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_constraint}{Constraint}}, \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_objective}{Objective}}, \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_function}{Function}}, ...); note that the base class makes no provisions about how this set is stored in order to leave more freedom to derived classes to implement it in specialized ways;
\item a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_variable}{Variable}} can be (temporarily?) fixed, i.\+e., not really a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_variable}{Variable}}.
\end{DoxyItemize}

Note that obviously a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_variable}{Variable}} has a value, but the methods for reading it must necessarily depend on the type of value it can take, and therefore must be demanded to derived classes.

destructor\+: it is virtual, and empty 

The destructor of the base \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_variable}{Variable}} class has nothing to do. However, it is important to remark that the destructor of any derived class is {\itshape not} assumed to scan through the list of \char`\"{}stuff\char`\"{} this \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_variable}{Variable}} is active in and remove the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_variable}{Variable}} from then. The idea is that \begin{DoxyVerb}*Variable are constructed before the "stuff" they are active
 in and destructed after them*
\end{DoxyVerb}


and hence, by the time that a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_variable}{Variable}} is destructed, the \char`\"{}stuff\char`\"{} it is active in have been destructed anyway; hence it is impossible (and useless) to remove from them. To avoid useless updating of data structures that may be about to be destructed anyway, the destructor of \+:\mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_variable}{Variable}} is {\itshape not} supposed to check the list of \char`\"{}stuff\char`\"{} it is active in, and just destroy the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_variable}{Variable}} (and the list with it).

This would of course leave any \char`\"{}stuff\char`\"{} in which the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_variable}{Variable}} is active in an inconsistent state, so care has to be exercised to ensure this does not happen by, if necessary, scan the list and do the removal {\itshape before} destroying the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_variable}{Variable}}.
