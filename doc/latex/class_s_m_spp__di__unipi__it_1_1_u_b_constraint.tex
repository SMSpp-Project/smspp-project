returns the absolute violation of the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_row_constraint}{Row\+Constraint}} 

The method computes and returns the absolute violation of the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_row_constraint}{Row\+Constraint}} corresponding to its current value \mbox{[}see \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_one_var_constraint_ad9256be16b98f3b557f54fa5e2118db7}{value()}}\mbox{]}. The value is positive if one of the two bounds is violated (of course not both can be) and it is the amount of violation; otherwise. An infinite bound (lhs == -\/ Inf$<$\+R\+H\+S\+Value$>$() or rhs == Inf$<$\+R\+H\+S\+Value$>$()) corresponds to a -\/ Inf$<$\+R\+H\+S\+Value$>$() violation whatever the value (even if it is the same infinity).

This method is provided because checking feasibility of a \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_row_constraint}{Row\+Constraint}} should reasonably require numerical tolerances, which are not there in the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_constraint_a29e571bbd4e2f1046c56e39c06633c4c}{feasible()}} method (because in general constraints could be checked \char`\"{}exactly\char`\"{}, say if only integer arithmetic is involved). This is somehow against the grain of \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_thin_compute_interface}{Thin\+Compute\+Interface}}\+: there could be parameters for doing this. However, this would complicate the interface, and could mean that each \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_row_constraint}{Row\+Constraint}} need to carry its own values of the parameters (while they are generally constant across many constraints of \char`\"{}the same type\char`\"{} in a model); via this method checking can be done outside of the \mbox{\hyperlink{class_s_m_spp__di__unipi__it_1_1_row_constraint}{Row\+Constraint}}, which for the time being we condiser the better alternative.
